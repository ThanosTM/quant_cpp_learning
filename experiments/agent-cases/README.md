# agent-cases/ — Agent 构造的性能优化案例

> 这里不是“教程”，而是**可执行的训练场**：Agent 先给你一个真实可跑的基线，再按你的指令逐步给提示、验证你的版本，最后才对答案。
> 与 [reproductions/](../reproductions/README.md) 的区别：复现是“把别人的结论在本机重测”；案例是“给你一个新问题，让你自己优化”。

## 一个案例包含什么

```text
agent-cases/NNN-<slug>/
├── README.md          # 任务书：场景、基线、验收标准、约束；不含答案
├── src/baseline.cpp   # 可运行基线（已实测）
├── src/attempt.cpp    # 你的修改入口（与基线同接口）
├── Makefile
├── run.sh             # 编译/对比/校验
├── checkpoints.md     # C1..Cn 的量化达标线
├── coach.md           # 分级提示（只在被要求时逐级揭示）
├── solution/          # 参考解 + 与基线的逐项对比
└── results/           # 基线、参考解、你的版本的 3 次中位数
```

任务书模板见 [templates/agent-case.md](../../templates/agent-case.md)。

## 难度分级

| 难度 | 基线特征 | 典型手段 | 验收 |
|---|---|---|---|
| L1 | 单一瓶颈，如伪共享或一次多余拷贝 | 对齐、去分配、预取、批处理 | p50 降低 15-30%，校验和一致 |
| L2 | 两个以上因素交互，如缓存容量 + 分支 + 同步 | 数据布局 + 分核 + 预取组合 | p50 与 p90 同时改善，至少一个负收益方案被识别 |
| L3 | 生产级权衡，如尾延迟、CPU 配额、可维护性 | 多方案对比、参数扫描、退化分析 | 给出 Pareto 结论，p99 不恶化，禁止用“平均变快”掩盖尾部 |

## 对话指令

| 你说 | Agent 行为 |
|---|---|
| 「构造一个性能优化案例，主题：___，难度 L2」 | 定义场景与基线 → 真实编译运行 → 测 3 次中位数 → 写任务书/验收/提示/参考解 → 更新本索引 |
| 「先别给答案，我要自己做」 | 只提供 `README.md`、`src/baseline.cpp`、`run.sh`；`solution/` 不展示 |
| 「给第 1 级提示」 | 只追加 `coach.md` 的下一级提示；不贴代码 |
| 「验证我的版本」 | 编译 `src/attempt.cpp` → 跑 3 次 → 与基线/参考解逐项对比 → 报告 C1..Cn 是否达标 |
| 「对答案」 | 展示 `solution/`、差异 diff、你的版本与参考解的指标差 |
| 「这个案例我过了」 | 归档你的 `attempt.cpp` 与结果，标记 mastered，并生成 5 道复习题 |

## Agent 构造案例的硬性流程

1. **定场景**：必须有一个可解释的业务热路径（行情、订单、期权重算、风控等），不能是裸数组求和。
2. **定基线**：基线必须真实编译运行；记录 p50/p90/mean、工作集、缓存行数、编译参数、机器信息。
3. **定瓶颈**：至少一个可以用本机探针或 A/B 证明的瓶颈；不能只凭“感觉慢”。
4. **定验收**：C1..Cn 量化；包含“校验和与基线一致”，防止改数学。
5. **写参考解**：参考解也必须真实跑通、校验和一致、3 次中位数；否则案例作废。
6. **写提示**：`coach.md` 按“观察指标 → 问题位置 → 方案清单 → 对答案”分级，前两级不得出现可直接粘贴的代码。
7. **做负例**：至少准备一个看起来合理但本机负收益的方案（例如 `_MM_HINT_NTA` 对应物、错误的对齐、错误的线程划分），用于训练判断力。
8. **更新索引**：本文件表格、根 README、CHANGELOG。

## 复用公共设施

- 计时、分位数、QoS、缓存行操作：`../common/bench.hpp`；
- 3 次运行聚合：`python3 ../common/summarize.py raw.csv --output summary.md`；
- 平台限制：macOS 无 PMU、无硬亲和性、24 MHz 计时，案例的任务书必须写明这些限制，不能要求参与者“用 perf 计数器证明”。

## 反作弊规则

- 禁止减少期权/事件数量、降低计算精度、跳过校验和；
- 禁止把 `solution/` 的代码直接复制进 `attempt.cpp` 后声称“自己做的”（Agent 可以对比 diff 并提示）；
- 禁止只报告均值而隐藏 p99；
- 禁止在基线里预先埋好“优化开关”再当作自己的成果；基线必须是一个诚实的朴素实现。
