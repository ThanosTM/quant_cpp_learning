# 核心系统开发岗 JD 分析（行情系统 / 交易系统方向）

> 最后核实日期：2026-09-02

「核心系统开发」在量化私募语境下通常指：**行情系统、交易/执行系统、风控系统、回测平台**等承载公司生产链路的系统，而非策略研究本身。它与「策略实现开发」的能力模型存在差异，本文以样本 JD 为准梳理。

## 1. 样本 JD 摘录

### 天演私募 · 资深 C++ 开发工程师（行情系统方向）[P0 官方 JD]

职责摘录：
- 建设离线行情数据链路，保障盘后行情数据的完整**落库、清洗与回放**能力，支撑**离在线数据一致性**。
- 参与行情系统的**架构演进与稳定性建设**，将行情能力沉淀为面向业务的数据服务。

要求摘录：
- 国内外重点大学计算机相关专业本科及以上，3 年以上工作经验。
- 熟练掌握 C++，熟悉常用数据结构和算法。
- 精通各种设计模式（[来源](https://app.mokahr.com/m/social-recruitment/tianyancapital/98901#/job/cdaca8e0-37bf-4f9a-a9ae-8ac5015e524b)）。

### 上海全频思维 · C++ 开发工程师（高频交易系统开发方向）[P2 招聘平台]

- 设计、开发和维护高效、可靠的 C++ 代码，用于量化交易平台的核心功能。
- 优化交易系统的性能，确保**低延迟环境下**的稳定运行（[来源](https://m.zhipin.com/zhaopin/ac5383c1e27f475c0nB53dm1Ew~~/)）。

### 垒昂资产 · 交易系统开发（社招面经中转述的岗位画像）[P2 社区]

- 策略团队提出需求并将计算数据 Input 到交易系统，交易系统设计并实现高效算法，将数据 Output 至接入券商（RPC 通信）。
- 交易实时性要求高，需持续优化交易系统的**响应速度与吞吐量**；订单、风险系数等数据量大，需**压缩并存储**到 SQLite 等（[来源](https://leetcode.cn/circle/discuss/l4Wg6c/view/0dqumG/)）。

## 2. 与通用 C++ 岗的差异点

| 维度 | 核心系统开发岗强调 | 对应本仓库模块 |
|---|---|---|
| 数据链路 | 行情接入 → 解析 → 分发 → 落库/回放，离在线一致性 | network + low-latency |
| 延迟与吞吐并重 | 微秒级响应 + 高吞吐；尾延迟（P99）意识 | low-latency |
| 进程间/主机间通信 | RPC、共享内存、组播行情协议 | network |
| 存储与序列化 | 列式/二进制协议、零拷贝解析、压缩 | low-latency + system 面试题 |
| 稳定性工程 | 架构演进、监控、容灾、回放测试 | interview/system |

## 3. 对本仓库的直接推论

1. `interview/system/` 类别专门承载系统设计题（如：设计一个行情网关 / 订单簿 / 回放系统）。
2. low-latency 模块规划需覆盖「零拷贝、内存池、序列化、共享内存通信」等链路级考点，而不仅是 CPU 级优化。
